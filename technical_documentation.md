# Техническая документация проекта «Нам хорошо вместе»

## 1. Обзор проекта
Программа «Нам хорошо вместе» помогает оценивать психологическую совместимость людей на основе модели базовых потребностей и предоставлять рекомендации по развитию дружеских, романтических и профессиональных отношений. Проект развивается по методу «набегающей волны»: на каждом этапе команда детализирует задачи, реализует функциональность, контролирует результат, фиксирует улучшения и готовится к следующему витку развития, не нарушая стабильность уже работающих возможностей.

### 1.1 Цели
- Создать многоязычную систему тестирования совместимости для разных возрастных групп.
- Генерировать красочные отчёты с прогнозами и юмористическими подсказками.
- Предоставлять встроенного AI-компаньона, который использует модель «Нам хорошо вместе» и базу знаний для точной поддержки пользователей.
- Обеспечить масштабирование до Telegram-бота, miniapp и полноценных web/iOS/Android-приложений.

### 1.2 Целевая аудитория
- Подростки (до 18 лет) с упором на безопасную дружбу и эмпатию.
- Молодые взрослые и пары, изучающие романтические отношения.
- Друзья, коллеги и команды, желающие усилить профессиональное взаимодействие.

## 2. Технологический стек
| Слой | Технологии | Назначение |
|------|-------------|------------|
| Клиент | **React**, **TypeScript**, **TailwindCSS**, Telegram WebApp SDK | Интерфейс miniapp и web/mobile версий, быстрое прототипирование UI. |
| Чат-бот | Python (aiogram/grammY) или Node.js | Версия 1.0 в Telegram. |
| API | FastAPI (Python) или NestJS (TypeScript) | Единая точка доступа к логике тестов, отчётам и ассистенту. |
| Сервисы | Worker-процессы на Python/TypeScript | Расчёт отчётов, отправка уведомлений, генерация PDF. |
| База данных | PostgreSQL, Redis, S3-совместимое хранилище | Хранение ответов, отчётов, сессий и ассетов. |
| AI | **Gemini API** (LLM), векторное хранилище (PGVector/Weaviate) | Контекстные ответы ассистента, поиск по базе знаний. |
| DevOps | Docker, GitHub Actions, Kubernetes/Serverless | CI/CD, масштабирование и наблюдаемость. |

## 3. Архитектура

### 3.1 Компоненты и сервисы
- **Question Bank Service** — управляет вопросами теста, версиями формулировок и переводами.
- **Scoring Engine** — рассчитывает индексы по потребностям «даю/получаю» и прогноз исходов отношений.
- **Report Service** — формирует визуальные отчёты, карточки и PDF.
- **Recommendation Engine** — подбирает упражнения, советы и юмористические подсказки.
- **AI Companion Service** — оборачивает Gemini API, добавляет системный тон, фильтры безопасности и контекст пары.
- **Knowledge Base** — текст модели «Нам хорошо вместе», научные справки, альтернативные методики; доступ через векторный поиск.
- **Feedback Collector** — собирает добровольную обратную связь и передаёт данные аналитике.
- **Admin Dashboard** — интерфейс для модерации контента и просмотра метрик.

Сервисы общаются через REST/GraphQL API и очереди (например, RabbitMQ) для асинхронных задач. В будущем допускается разделение на микросервисы; на ранних этапах возможен модульный монорепозиторий.

### 3.2 Клиентские приложения
- **Telegram Bot 1.0** — основной интерфейс для первых пользователей; обеспечивает прохождение теста двумя участниками, быстрый отчёт и доступ к ассистенту.
- **Telegram Mini App 2.0** — визуально насыщенный интерфейс на React + TailwindCSS, использует те же API, что и бот.
- **Web/iOS/Android 3.0** — полноценное приложение на React (Next.js) и React Native/Flutter с общим кодом логики и стилей.

### 3.3 Управление состоянием
- В miniapp и web-клиенте состояние хранится через React Query/Zustand (локальные данные теста) плюс серверное состояние из API.
- Для сложных сценариев (история тестов, чаты) используется Event Sourcing или Saga-паттерны на сервере.
- Контекст ассистента хранится в краткоживущих сессиях (Redis) и очищается после завершения диалога.

## 4. Данные и модели
- **Профиль пользователя:** язык, возрастная группа, предпочтительный канал связи.
- **Результаты тестов:** баллы по шести потребностям в плоскостях «даю/получаю», заметки, таймстампы.
- **Совместимость пары:** агрегированные индексы, прогноз по четырём исходам, список рекомендаций и юмористические подсказки.
- **Ассистент:** контекстные фрагменты отчёта, выдержки из базы знаний, журнал взаимодействий для аналитики.
- **Обратная связь:** оценка полезности отчёта, точности рекомендаций, предложения по улучшению вопросов.

## 7. Стратегия тестирования
- **Юнит-тесты:** расчёт индексов по потребностям, прогноз вероятностей, валидация возрастных ограничений.
- **Интеграционные тесты:** прохождение теста вдвоём, генерация отчёта, запуск ассистента с контекстом.
- **Ручные проверки:** консольный сценарий `python -m bot.simulator --language ru` для отладки вопросника и поведения ассистента без Telegram.
- **UX-тесты:** проверка дружелюбности интерфейса, читаемости графиков и юмористических блоков.
- **Нагрузочные тесты:** имитация одновременных тестов и обращений к ассистенту.
- **Безопасность:** проверка фильтров на нецензурные выражения, корректного удаления персональных данных по запросу.

## 8. Деплой и инфраструктура
- **Контейнеризация:** каждый сервис упаковывается в Docker-образ с едиными стандартами логирования.
- **CI/CD:** GitHub Actions запускает тесты, линтеры и деплой на staging/production среды.
- **Мониторинг:** Prometheus + Grafana, логирование в ELK или OpenSearch, алерты в Slack/Telegram.
- **Окружения:** dev (локально через Docker Compose), staging (Kubernetes), production (Kubernetes/Serverless).

## 12. Этап 0 — Аналитика и дизайн (выполнено)
### 12.1 Персоны и сценарии
- **Подросток-исследователь (13–17 лет):** ищет безопасную дружбу, боится насмешек. Важны принятие и безопасность.
- **Студент/молодой специалист (18–27 лет):** строит дружбу и романтические связи, ценит драйв и признание.
- **Партнёр в долгих отношениях (28–45 лет):** хочет стабильности, заботы и совместного развития.
- **Коллега/тимлид (25–50 лет):** фокусируется на командной работе, материальной поддержке и честной обратной связи.

Каждая персона сопровождается картой мотивации, юмористическими триггерами и ожиданиями от отчёта. Проработаны сценарии «Старт + приглашение», «Повторное тестирование», «Экстренный совет у ассистента».

### 12.2 Голос бренда и визуальная концепция
- Тон: дружелюбный, понятный ученику средней школы, с лёгким здоровым сарказмом.
- Метафоры: суперсилы, коллекции странных носков, обмен любимым кофе.
- Подростковая ветка исключает намёки на интимность, делает акцент на безопасности и взаимной поддержке.

### 12.3 Карта опыта пользователя
1. Приветствие → выбор языка и возраста.
2. Вводная с согласием «не руководство к действию».
3. Личное тестирование (12 вопросов: 6 потребностей × 2 ориентации).
4. Передача кода второму участнику.
5. Парный отчёт с прогнозом исходов и рекомендациями.
6. Вызов ассистента, оставление обратной связи, план повторного теста.

### 12.4 Информационная архитектура
- Контентные блоки отчёта: заголовок, общий балл, прогноз, описание потребностей, вызовы `/feedback` и `/companion`.
- База знаний ассистента формируется из файла `description of the psychological compatibility model.txt` и тематических тезисов.
- Путь масштабирования: Question Bank → Scoring Engine → Report → AI Companion как отдельные сервисы.

## 13. Этап 1 — Telegram-бот 1.0 (реализация)
### 13.1 Архитектура модулей
- `bot/config.py` — загрузка конфигурации.
- `bot/localization.py` — словари переводов RU/EN и helper `translate`.
- `bot/questions.py` — банк вопросов с ориентациями «получаю/даю», возрастными фильтрами и примерами.
- `bot/compatibility.py` — расчёт совпадений и вероятностей исходов.
- `bot/reporting.py` — формирование текстового отчёта с тоном и рекомендациями.
- `bot/simulator.py` — консольный симулятор для локальной проверки вопросов, отчёта и ассистента без Telegram.
- `bot/storage.py` — SQLite-хранилище (готово к миграции в PostgreSQL).
- `bot/assistant.py` — правило-ориентированный AI-компаньон с доступом к базе знаний.
- `bot/main.py` — FSM-логика бота, обработка команд `/start`, `/feedback`, `/companion`.
- `pyproject.toml` — зависимости и dev-инструменты.

### 13.2 Схема данных
- `sessions(id, code, language, age_group, created_at)` — идентификатор пары.
- `participants(session_id, participant_index, telegram_id, name, finished)` — пользователи и статус прохождения.
- `answers(session_id, participant_index, need, orientation, score)` — оценки по шкале 1–5.
- `feedback(session_id, message, created_at)` — добровольные отзывы для обучения модели.

### 13.3 Пользовательские сценарии
1. `/start` → выбор языка → «начать» или «у меня есть код».
2. Выбор возрастной группы, согласие, ввод имени.
3. Серия вопросов с подсказками и юмором.
4. Передача кода второму участнику и ожидание.
5. Автоматический отчёт для обоих участников и приглашение к ассистенту.
6. `/companion` — контекстный совет по слабым и сильным потребностям, `/feedback` — форма обратной связи.

### 13.4 Отчёт и рекомендации
- Структура отчёта: заголовок, общий процент совместимости, прогноз исходов, статус каждой потребности (`need_status_*`).
- Юмор и мотивация встроены в локализацию (`thanks_first`, `tone_high`, «подготовьте места для кубков»).
- Рекомендации собираются из Need Compatibility, подсветка зон роста и силы.

### 13.5 API и команды
- `/start` — новый тест или присоединение по коду, управление клавиатурами через FSM.
- `/feedback` — сохранение сообщения в таблицу `feedback`.
- `/companion` — диалог с ассистентом на основе `AssistantContext` (отказ при off-topic или грубости).
- Inline-кнопки `score:1..5` — фиксация ответов.
- Переменные окружения: `BOT_TOKEN`, `BOT_STORAGE` (путь к SQLite-файлу).

### 13.6 Ассистент и база знаний
- Фильтрация нецензурной лексики и вопросов вне контекста.
- Совет формируется по наименее и наиболее совпавшим потребностям с ссылкой на базу знаний.
- Сниппет модели берётся из исходного файла (первые 400 символов), планируется переход на векторный поиск.

### 13.7 Ограничения и дальнейшие шаги
- Требуется внедрить Docker/CI, автоматические тесты и визуальные отчёты.
- Ассистент пока работает на правилах; интеграция с Gemini API — следующая итерация.
- Добавить A/B тестирование вопросов, напоминания о повторном тесте, хранение истории результатов.
